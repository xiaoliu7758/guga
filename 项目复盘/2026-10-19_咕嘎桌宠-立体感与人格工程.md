## 一句话结论

立体感**不是**做出来的 3D，是素材里已经烘焙好的三件事——单一主光、三种材质同框、脚底那团软影——代码只补了「微动」这最后一层，把静图变成「在场」。
傲娇**不是**靠「才不是呢」这类台词，数据显示那类句式只占 2~4%；真正撑住人格的是自称「本鹅」（54% 的台词）、口癖「咕嘎」（86%）、以及一个 1.4 秒、首帧反方向的摇头动作。
项目能跑、也有 MIT 和脱敏配置，但**现在还不能被别人直接复用**——卡点不是文档不够，是 1763 行的 `pet_window.py` 里没有一条「内核 / 角色 / 业务」的边界。

## 一、立体感：拆成 5 条可复制的判据

| 判据 | 这张图里的证据 | 换角色必须保留 |
|---|---|---|
| **1. 单一主光，方向写死** | 左上打光：头罩左侧一条宽柔高光带，右侧整体压暗；鼻尖高光在左上；脸右半有阴影 | 所有表情图的主光方向必须一致，否则切表情会像换了个人 |
| **2. 三种材质同框** | 企鹅外套＝宽而软的低强度高光（毛绒/硅胶）；脸＝几乎无高光但有透光红晕（次表面散射）；金属挂钩＝极小面积、极高亮度、边缘锐利（硬镜面） | 一套素材里至少要有 **1 个硬反射物件**。没有它，整体会退化成塑料贴纸 |
| **3. 几何球形化** | 头、身体、脚全是球/椭球，2~3 头身；除挂钩外几乎没有锐角 | 球体在单光源下天然产生「亮部→明暗交界→反光→投影」四段，大脑对体积的判读是硬连线的 |
| **4. 接地投影** | 脚底有一团比脚略大、边缘完全虚化的软影 | 影不能省。它是「站在桌上」和「飘在桌面」的唯一区别 |
| **5. 背景剥离** | 背后是纯色浅灰绿、无纹理；主体 alpha 抠得干净 | 等于给了一张「无限远背景」，视觉注意力全落在主体上 |

### 代码补的最后一层：让它「活」

- **影**：`_draw_shadow` 用径向渐变画椭圆，宽＝0.5 图宽、高 11px、贴在底部上方 8px，alpha `40 → 16 → 0`。这是伪环境光遮蔽，几行代码，但立刻把角色「按」在桌面上。
- **呼吸**：4 秒一个周期、幅度 **0.5%**。小到看不出，但大脑会把它读成「有体积的东西在起伏」。
- **挤压回弹**：`trigger_bounce` 把身体压到 0.86，同时横向 `2 - sq` 反向补偿，避免「压扁不变形」的塑料感。
- **不可预测的小动作**：眨眼 2.5~6 秒随机、翅膀抖 3~9 秒、闲置小动作 8~16 秒。**随机性本身就是「活着」的信号**——固定周期会立刻被识破是动画。
- **说话点头**：嘴张开量 × 1.6px 的垂直位移。

### 为什么最后没走真 3D（这条最值钱）

`ui/gl_penguin.py` 有 436 行，用 OpenGL 离屏渲染程序化球体建模（身体/肚皮/眼睛/喙/翅膀/腮红全用椭球拼），能跑，接口也和 2D 动画器对齐了。
但配置里 `3d_penguin: false`，默认关闭，注释写的是「默认 2D 精灵保证稳定显示，3D 出图失败自动回退 2D」。

**结论：立体感的 90% 在素材的光照与材质里，3D 几何只贡献 10%，却要付 10 倍的复杂度和不稳定性。**
判据：角色需要「转身 / 多角度 / 换装 / 实时换色」才值得上 3D；只是「站在那里卖萌」，2D 原画全胜。

## 二、傲娇：五件套，不是文案库

先看数据（57 条台词，逐条统计）：

| 关键词 | 覆盖台词 | 说明 |
|---|---|---|
| 「咕嘎」 | 49 句 / **86%** | 口癖，每句开头，制造非人感 |
| 「本鹅」 | 31 句 / **54%** | 自称体系，权力倒置的地基 |
| 「…」 | 12 句 / 21% | 话说一半，傲娇的关键是「不把话说完」 |
| 「才不是 / 勉为其难 / 仅此一次 / 反正」 | 各 1~2 句，合计 **6%** | **经典傲娇句式其实很少** |
| 平均句长 | **13.8 字** | 短句，急了才像傲娇，长了变念稿 |

表情配比也说明问题：`playful`（得意/坏笑）**18/57 = 32%**，比 `happy` 的 18% 还多。
**人格的视觉底色是「得意」，不是「开心」。** 换成 happy 占三分之一，角色立刻变傻白甜。
动作分布：46% 的台词不带动画（站着说话），其余依次 bounce 19% / tsundere 12% / shake 11% / peek 7% / point 5%。

### 四个真正起作用的机制

1. **权力倒置的称呼**：它叫用户「饲养员」，自称「本鹅」，动词是「命令你 / 允许你 / 伺候本鹅」。地位在上，但行为上离不开你——**嘴上凶 + 行为黏**，这才是傲娇；只凶不黏是恶役。
2. **动作时长与相位**（最硬的一条，纯代码）：

   | 动作 | 时长 | 起始姿态 | 读起来 |
   |---|---|---|---|
   | `bounce` | 0.45s | 直接起跳 | 立刻开心 |
   | `shake` | 0.50s | 直接抖 | 受惊 |
   | **`tsundere`** | **1.40s** | **先反方向 −2.5°** | **慢半拍、先抗拒、再小幅度摇（幅度仅 4.5°）** |

   同样的台词配 0.45 秒的动作会变成「活泼」，配 1.4 秒且首帧反向才变成「不情愿」。**人格是时长和相位，不是形容词。**
3. **`peek` 偷看**：横向轻移 12% 图宽 + 2.5° 小倾。说完狠话偷偷瞄你一眼——**身体语言比台词有效**。
4. **动作→表情强制映射** `GESTURE_EXPR`：指指点点永远配 playful 脸、受惊永远配 surprised。这条映射保证了「凶话配笑脸」这种穿帮不会发生。

### 另外两条容易被忽略的

- **音色是人格的一部分**：`zh-CN-XiaoyiNeural`，语速 +15%、音调 +14Hz。音色错了，同样的台词会从「傲娇」变成「骂人」。
- **需求是真的，表达是否定的**：状态机 20 秒一跳，饥饿 −0.4 → 约 **83 分钟**从满到空；饿了才触发「本鹅命令你，立刻上菜」。台词不是随机播放，是**有求于你但不说**。
- **负面情绪有边界**：sad 台词是「算了，反正你也不在意」，是撒娇式抱怨，从不真的攻击用户。傲娇的底线是**永不真伤害用户**。

## 三、可以学的 6 个工程习惯

1. **单入口 `_say(text, expression, action)`**：所有行为走一个函数，气泡、表情、动作、TTS 一次到位。人格类功能最怕「各处直接改表情」，一多必穿帮。
2. **每层都有 Plan B**：3D 挂了回 2D、官方 Qt 找不到用 wheel 自带、UAC 被拒降级为普通模式、Edge TTS 失败退豆包。**桌宠不能因为某个可选功能挂掉就消失**。
3. **pythonw 下崩溃是无声的**：`launcher.py` 把 stdout/stderr 重定向到 `startup.log`，再挂 `excepthook` 弹 MessageBox。这是所有无控制台 GUI 项目的通用坑。
4. **跨线程只走信号**：`QMediaPlayer` 只在主线程操作，后台线程只合成 mp3，通过 `pyqtSignal` 回主线程播放。
5. **素材与逻辑分离**：6 张表情图 + 2 个 GIF，改名即换角色。这为第四节的分层留了门。
6. **注释里写「为什么不这么做」**：3D 为什么关、拔线失败为什么降级、蒙特卡洛为什么用 600 次而不是 2000 次——这些「否决理由」比「实现说明」值钱十倍。

## 四、复用：先拆边界，再谈文档

### 现在的真实卡点（都有证据）

| 卡点 | 证据 | 后果 |
|---|---|---|
| 巨石窗口类 | `pet_window.py` 1763 行 / 80KB，UI、战棋、语音、智能体、MCP 全在一个类 | 别人改任何一处都要读懂全部 |
| 没有接口边界 | 10 个 `.bak_*` 备份共 404KB；25 处未提交改动 | 迭代方式是「就地改 + 存副本」，说明还没有稳定到可以对外承诺的接口 |
| 素材规格不统一 | 6 张表情尺寸各异：227×326 / 228×328 / **244×351** / **216×323** / 241×327，靠 `KeepAspectRatio` + 居中兜底 | 换素材后切表情会跳动（见未验证项） |
| 分辨率已到顶 | 原画 227px 宽，显示 250px → **已放大 1.1 倍**，且没有 2x 素材 | 高分屏上会糊，且无法再放大 |
| Qt 路径硬编码 | `launcher.py` 指向 `~/.zcode/tools/qt/5.15.2/msvc2019_64` | 有 wheel 自动探测兜底，别人机器能跑，但不优雅 |
| 影不跟随位移 | `_draw_shadow` 画在 `translate` 之前，`peek` 侧移 12% 时影子留在原地 | 快速侧移时身体和影子会短暂错位 |

**做对的地方别改**：MIT 协议、`ai_config.example.json` 已脱敏、`.gitignore` 排除了 `ai_config.json` / `*.bak` / `runtime/chat/`。这三件事是能给别人看的前提。

### 抽成三层（建议这样切）

| 层 | 内容 | 规模目标 | 对外接口 |
|---|---|---|---|
| **A. PetCore 内核** | 无边框透明置顶窗 + 精灵动画器（呼吸/眨眼/挤压/表情淡入）+ 接地影 + 气泡 + TTS | ≈300 行 | `set_character(dir)` / `say(text, expr, action)` / `set_state(dict)` / `on_click(cb)` |
| **B. Persona Pack 角色包** | 纯数据，零 Python | — | `character.json`（名字/称呼/自称/口癖/音色/表情配比）+ `speech.json`（场景→台词+表情+动作）+ `expressions/` + `stickers/` |
| **C. 业务插件** | 战棋军师、助教、MCP 智能体 | 各自独立 | 只通过 signal 挂到内核，不许 import 内核内部状态 |

> 抽取顺序建议：先抽 `sprite_animator` + `_say`（依赖最少，597 行里已经有完整动画逻辑），再抽窗口壳，最后把战棋/智能体降级为插件。反过来做会陷在 `pet_window.py` 里。

### 素材规格：这才是复用的真正契约

别人复用时 80% 的坑是素材，不是代码。把这五条写进 README 顶格：

1. 画布统一 **512×736**（等比 @2x），PNG-32。
2. **脚底锚点固定在画布 (0.5, 0.94)**，6 张表情必须同画布、同锚点，**只换脸不动身体**。
3. 主光固定在**左上 45°**，所有表情一致。
4. 每套素材至少含 **1 个硬反射物件**（金属/玻璃/漆面），否则立体感撑不住。
5. **不要把投影烘焙进 PNG**，影由代码画；否则换背景色时影子会露馅。

### 让别人 30 分钟接入的 5 步

1. `git clone` → `pip install -r requirements.txt`
2. 复制 `ai_config.example.json` → `ai_config.json`，只填一个 `api_key`（不填也能站着卖萌，只是不会说话）
3. 把自己的 6 张表情按上面的规格丢进 `expressions/`
4. 改 `character.json`：名字、怎么称呼用户、自称、口癖、音色、表情配比
5. 双击 `启动企鹅.bat`，改台词只用编辑 `speech.json`，**不碰 Python**

### 人格参数清单（别人最容易抄漏的部分）

- 自称占台词比例（本鹅 54%）
- 口癖覆盖率（咕嘎 86%）
- 主要表情配比（playful 32%，**不是 happy 最多**）
- 带动作台词比例（54%）
- 标志性动作的时长与首帧方向（tsundere 1.4s、首帧 −2.5°）
- 语速/音调偏移（+15% / +14Hz）
- 状态衰减速率（饥饿 −0.4/20s ≈ 83 分钟）

## 验收线

1. 换一套新角色素材，**不改一行 Python**，30 分钟内能让它站在桌面上说话。★
2. 切表情时角色包围盒位移 ≤ 2px（当前**未达标**，6 张图尺寸不一致）。
3. 2x 屏下 250px 显示不糊（需 2x 素材，当前 1.1 倍放大，**未达标**）。
4. `tsundere` 动作时长 ≥ 1.2s 且首帧反方向，否则人格会退化成「活泼」。
5. Qt / 3D / TTS / API 任一挂掉，桌宠仍能正常显示与拖拽。★

## 对客户（或队友）一句话

这是一个能站着卖萌、会说话的桌面企鹅：立体感靠素材的光照和脚底那团影，性格靠自称「本鹅」、口癖和慢半拍的摇头动作。换角色只需要换 6 张图和一份台词表，不用改代码。

## 未完成 / 未验证

1. **「切表情会跳位」是读代码推断，没有实测。** 依据是 6 张图尺寸不一致 + `scaled(KeepAspectRatio)` + 居中；没有真跑起来逐帧截图比对像素位移。
2. **3D 模式的实际观感与帧率没测。** 只读了 `gl_penguin.py` 和 `pet_3d.log`（内容仅 `3D disabled` 类字样），没有把 `3d_penguin` 打开跑过。
3. **「影不跟随 peek」只验证了代码顺序，没验证视觉影响。** 12% × 250px ≈ 30px 的错位在 1.1 秒内是否肉眼可辨，未截图确认。
4. 词频与表情/动作分布是脚本统计的（57 条全量），但**没有做跨场景权重**——idle 场景触发频率高于其它场景，按触发频次加权后的真实占比会与这份统计不同。
5. 第四节的 A/B/C 三层只是方案，**没有落地成代码**，行数目标（≈300 行）是估计值。

## 自测（先别看答案）

1. 如果把 `tsundere` 的动作时长从 1.4s 改成 0.45s、首帧改成 0°，你预测会在哪一层坏掉？坏成什么样？
2. 换了一套 512×736 的新素材，分辨率更高了，为什么反而要第一个检查「锚点」而不是「清晰度」？
3. 为什么把 happy 表情的配比从 18% 提到 40%，角色会「不像傲娇」？

## 答案

1. **坏在「人格层」，不是动画层。** 代码不会报错，动作照样播完，但观感从「不情愿地摇一下」变成「爽快地蹦一下」——同一句话从傲娇变成活泼。这类退化没有任何报错，只能靠人眼比对，所以要把它写成规格（≥1.2s + 首帧反向）。
2. **因为锚点决定「切换时会不会跳」。** 分辨率只影响清晰度，锚点影响的是 6 张表情在同一个窗口里是否对齐；锚点一错，眨眼瞬间角色会平移几像素，比糊更刺眼。高分辨率素材往往重画过构图，锚点最容易变。
3. **因为傲娇的底色是「得意」不是「开心」。** 数据里 playful 占 32%、happy 占 18%；happy 一多，角色就从「嘴硬心软」变成「有求必应」，权力倒置的设定塌了。表情配比本身就是人格参数，不是美术风格。
