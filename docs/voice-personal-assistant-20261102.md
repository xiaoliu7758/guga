# 常驻语音个人助手：任务分流、页面操作与失败解释

版本：`2026-11-02.voice-assistant.1`。

## 本次故障的证据

当前工程和运行中的源代码桌宠通过本地 MCP 身份核对一致。升级前运行版本为 `2026-11-02.local-first.4`，完整访问开启，Windows 管理员身份。

用户那次“关闭页面”任务编号 `91c80a0d3ecf48e8a749bc4be61e2036`：`events=[]`、`operations=0`，停止在模型连接阶段，未执行关闭或其他工具操作。旧记录没有异常链、HTTP 状态及耗时，不能事后认定是 DNS、代理、TLS 或服务端哪一个故障。新的单次连接探测 HTTP 200、约2.09秒，并不能证明之前没有短暂故障。

对话记录确有将关闭当前页面称为复杂任务并要求确认的问题。确认成功后的“交给DSH执行”是写死的播报，不能据此认定真正启动过 DSH。该次任务实际在本地 SelfAgent 留档，DSH 状态没有相应执行记录。

## 改造结果

1. **日常优先本地。** 页面关闭、软件切换、读取文件、单个函数或一行代码不因涉及“项目/代码/仓库”就升级。自动 DSH 需要工程意图和工程范围；用户明确指定 DSH 或手动固定后端也会生效。任务分流本身不调用模型。上传/发布仍沿用原有确认语义，播报不会把它冒称复杂工程。
2. **页面和浏览器分开。** “关闭当前页面/网页/标签页”和“关闭浏览器”不同；支持“我的意思是让你……”等口语纠正。当前前台必须能确定是目标浏览器。先识别选中标签身份，再确认焦点和身份没变，只发送一次关闭输入，最后验证该标签消失、数量减少或目标窗口关闭。
3. **自然语言执行器共享同一个标签工具。** `browser(action=close_tab)` 可供未命中快捷短语的任务使用；本地执行器和 DSH 工具桥共用。关闭结果不确定时在该任务内保存回执、抑制重复发送，不能把又关闭一个标签当作重试。
4. **解释不依赖故障中的模型。** 主程序按实际工具记录生成失败说明：失败层次、原因的确定程度、工具是否调用、已有结果、下一步。模型连接异常保留异常类型链、系统错误码、HTTP 状态、域名、请求序号及耗时，不记录上游响应正文、请求头或密钥。工具失败保留退出码和脱敏错误。
5. **语音协议同步。** 千问只播报真实执行反馈，不把简单操作重述成复杂任务，不把模型连接失败变成网页连接失败。“刚才为什么失败”“查看任务诊断”可以直接读当前对话的本地记录。没有足够证据时明确说无法确定。
6. **保持界面可响应。** 标签操作由工作线程调用独立进程；UIA 进程最多7秒。超时会终止执行器并报告结果未知，绝不自动重发。桌面关闭期间不并发启动另一个桌面任务。Windows 前台切换静默失败时尝试已有的有界线程输入挂接，再核对焦点；仍失败则不发关闭输入。

## 常驻与隔离的选择

参考 Muse 的个人助手、持久执行与隔离电脑理念，nanoMuse 的桌面执行器/会话组织，以及 UFO 的结构化控件与原生操作结合。现有咕嘎已有常驻外壳、语音、任务档案和记忆，本次在这条链路上改造，没有整包替换助手，也没有复制 nanoMuse 的 GPL 源码。

- 当前桌面操作使用宿主 Windows，继承咕嘎的现有完整访问和实际 Windows 身份。虚拟机无法直接代替宿主上的页面关闭。
- 7秒子进程是故障隔离，**不是安全沙箱**；工作目录隔离也不等于文件权限隔离。
- 本机存在 Docker CLI，但探测时引擎未运行；未找到可直接启动的 Windows Sandbox。本次没有安装虚拟机、启动 Docker 引擎、创建系统服务、调整UAC或声称已建成安全沙箱。
- 需要运行不可信软件、自治修改自身或后台拥有独立浏览器时，应另配真实 VM/容器、受限共享目录及明确的回传接口。本次没有把任意系统命令伪装成隔离执行。
- 本次没有把UI进程改为退出外壳仍能继续干活的独立系统服务；常驻运行时可以执行后台任务，完整 Muse 式跨设备服务仍是后续范围。

## 验证

- 相关离线与 Qt 集成回归共 **131项**通过，包含语音原话纠正、简单任务不确认/不转DSH、重复关闭抑制、焦点失败、目标变化、结果不确定、网络各层分类、已有工具结果保留、现有任务停止与DSH会话行为。
- 新开独立 Edge 测试窗口：选中测试标签关闭、另一标签保留；用户原页面未触碰，测试进程清理完毕。
- 新开独立默认豆包浏览器测试窗口：不加强制无障碍启动参数，实际标签关闭和保留页核验通过；用户原页面未触碰，测试进程清理完毕。
- 真实 Go 模型受控验收：2次模型请求，选择 `browser.close_tab`；模拟两个窗口目标不明，工具明确没有发送输入，最终失败说明包含原因与下一步。没有真实桌面输入。
- 另一次有12秒读取上限的模型探测确实超时，新宿主如实报告“读取响应超时、0个工具操作”；它与真实浏览器失败被分开记录。未自动重放副作用。
- 未调用千问付费/免费语音 API，也未替用户录制麦克风。真实语音识别与听感仍需实际通话观察；不能把文字和工具验收当作麦克风验收。
- 原有动画资源的 `ResourceWarning` 在测试中仍存在，不影响本次断言，未扩大本轮范围去重写动画资源加载。

证据：`runtime/voice-assistant-qa/`。原任务诊断仍在 `runtime/agent-tasks/`；后续错误会附结构化诊断。
