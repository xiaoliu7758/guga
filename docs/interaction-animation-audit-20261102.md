# 咕嘎动画与助手运行机制：本阶段检查

## 已确认的问题

- joy_sway_dance 两张姿势图局部形变，用户否定视觉质量；eyes_shake_dance 旧候选曾有残影。
- 曾把帧数、边界和可加载测试当成视觉验收，不成立。本轮抽查连续时间点仍只能用于定位问题，不能证明整段动作自然。
- 动画播放同时叠加桌宠程序摆动，增加失真；不是 dsh-pet 那种完整关节动作视频。
- 主任务气泡每 12 秒重复上一条状态；DSH 侧按开始事件播报步骤，不是事实摘要。

## 源码修正（尚未更新安装包或正在运行的应用）

- 两个异常动作保持文件不删除，visual-review.json 标记 rejected；运行时不加载。
- 增加动作审核关卡：形象一致、连续动作、无残影、结构正常、循环接缝全部通过且绑定帧 SHA256 才能加载。脚本安装旧舞蹈被禁止。
- 旧舞蹈入口暂用原画轻摆，幅度减小、不做形体缩放；菜单如实叫“轻轻摆动”，不是复杂舞蹈交付。
- 主任务约 180 秒汇总实际工具回执，不显示原始推理、敏感工具参数或模型自称成功；无新回执只提醒一次停滞，避免重复。
- 允许在等待后台工具时播报进度；用户说话或助手正在播放时延后。未做真实麦克风长通话验收。
- DSH 任务带当前成员人格、工作方法与该成员检索记忆；事件带发起者编号，结束内容存入该成员记忆。
- DSH 返回只算执行器返回，不自动宣称整个目标已独立验证。启动失败和异常都有结束事件。
- 三成员共享电脑工具，各有不同工作方法；不是三套独立训练过的模型。SQLite 私有记忆按 agent_id 隔离，已有测试验证不串号。
- DSH 当前标准 status 事件只有执行阶段信息；具体工具回执适配需以实际 headless 事件样本继续验证，不能把 step_start 当成操作成功。

## 下一阶段及验收

优先寻找同形象、固定镜头、全身不出画、清晰背景的完整源动作视频；透明化后先连续播放，再抽查轮廓、脚底、脸、发卡与锁链，最后检查循环接缝。每个动作单独批准，不能以另一动作通过代替。

待素材合格后再接动作池：待机 / 点击 / 说话 / 工作 / 等待 / 入睡 / 睡眠循环 / 唤醒。困倦保持到用户主动交互，拖拽仍保持普通移动。

本阶段源码离线验证：9项进度/sidecar专项 + 62项语音交接/身份/私有记忆/悬浮UI/异常动画拒载/表情回归，均通过（分开运行退出码0）。不包含新动画视觉通过、真实语音API测试、最终EXE验收。
