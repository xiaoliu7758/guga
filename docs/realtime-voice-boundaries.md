# 咕嘎长语音能力的当前边界

更新：2026-11-05。以下依据当前代码和已完成的离线/协议测试，区分“已经具备”“有条件可用”“尚未验证”。持续通话的最新实测见 [持续通话修复与验收](voice-continuity-20261105.md)。

## 已经具备

- 千问端到端实时语音负责麦克风持续收音、轮次检测、语音打断和原生音频回复；聊天模型负责实质任务。
- 语音任务和文字共享同一会话、项目、工具和任务检查点。
- 执行期间可以问进度、追加要求或明确停止；明确停止、结束通话或关闭窗口会取消任务。
- 后台任务和战棋事件可以在用户停止说话、当前回答和播放结束后插入同一通电话主动播报。
- 语音回答会流式显示在咕嘎头顶气泡；点击气泡打开同一会话。
- 对话文字保存在本地会话数据库；通话本身不保存音频。
- 普通 Edge TTS 的原有路径仍然保留，实时语音使用另一条 WebSocket 连接。
- 默认不启用声纹门禁；用户可选择本地主人声纹验证，启用后非主人音频在进入云端前被替换为静音。
- “停止对话”“打开网页/软件”“搜索”有本地快速路由，不进入 DeepSeek，默认不生成语音回复。

## 时长和上下文边界

| 能力 | 当前上限 | 实际含义 |
|---|---:|---|
| 单次通话 | 默认 0（不限时） | 只有用户显式设置正数时才按该分钟数主动结束 |
| 空闲结束 | 默认 0（不自动结束） | 正数才启用空闲计时；0 时静音、等待不结束通话 |
| 客户端定时续接 | 已移除 | 不再每 110 分钟主动断开；真实传输故障的恢复不能当作持续连接成功 |
| 千问模型历史 | 50 轮 | 服务端对实时对话历史的限制，不能等同于完整长期记忆 |
| 本地语音历史 | 100 条消息 | 发送会话配置时最多取最近 80 条，并限制为约 16000 字符 |
| DeepSeek 会话历史 | 当前会话最近 40 条 | 长任务另有 Task Journal 检查点 |
| 单次任务 | 默认 900 秒、80 轮思考、160 次工具 | 达到后暂停并保存检查点，不是无限执行 |
| 传输故障恢复 | 指数退避，最长 15 秒间隔 | 用户结束可立即中止；鉴权、权限、额度错误明确停止，不反复付费调用 |

“长对话”目前是**单次长时通话 + 本地文字历史和检查点续接**，不是永久语义记忆。超过窗口的早期对话会丢失或被压缩；不同项目的记忆不会自动融合。

## 语音交互边界

- 耳机模式允许边说边打断；外放模式在生成和播放期间抑制麦克风输入，以避免回录。当前没有软件声学回声消除。
- 支持语音 barge-in，但用户开口后要先判断是“查询进度、追加要求、停止任务还是新话题”。当前是规则加模型判断，复杂歧义仍可能误判。
- 麦克风背景噪声、方言、同音词和多人说话会影响识别。程序不会把识别失败当作任务成功。
- 当前默认使用 `server_vad` 和 600 ms 断句等待；用户长时间思考或连续说多个任务时，仍可能被切成多次提交。断句到服务端创建回复之间也属于该语音轮次，客户端不会在此时插入新回复或后台配置更新。
- 敏感不可逆操作的语音确认需要专门处理，不能把普通“好”“嗯”直接当成高风险授权。公开版当前采用完整访问和工具侧确认边界，仍需继续细化审批状态机。
- 不能用实时语音识别系统音频。它只处理配置的麦克风输入。

## 任务执行边界

- 常见软件启动、网站打开及当前浏览器单步操作从完整转写直接进入本地快捷执行器，不等待任务模型。复杂任务才使用 `ask_deepseek` 进入本地工具循环；源码工程任务可交给 DSH，共享会话和检查点。
- 同一时刻只有一个主任务循环；执行期间的新语音进入追加队列，除非明确停止。
- 后台战棋或长任务可以在通话中汇报，但如果用户结束通话或关闭窗口，相关任务会被取消。
- 任务最终是否成功由工具回执和完成门槛决定，模型不能仅凭自己的文字声明“已完成”。
- 桌面上的外部软件可能启动成功但后续操作失败；必须看窗口、UIA 属性、文件哈希、命令退出码或游戏日志。

## 已验证和未验证

已通过：离线实时语音配置、工具调用去重、打断/迟到结果丢弃、同通话主动播报、隐藏气泡、点击返回原会话、长任务追加要求和停止。真实服务原生合成语音在同一连接持续 10 分钟，26 次转写、56 次回复、0 断线/重连/协议错误；本机音频设备另完成 90 秒静音检查。未做数小时真实麦克风稳定性测试。

未充分验证：真实麦克风下数小时通话、蓝牙耳机切换、不同声卡、噪声环境、多人对话、方言、外放回声、网络抖动、平台额度耗尽时的体验、真实工具任务在执行中反复追加后的恢复可靠性。

## 下一步边界提升

1. 继续完善已有的按进程会话诊断日志；只保留连接、轮次与工具时序计数，不记录音频、转写、提示词或凭据。
2. 增加“语音草稿”和“正式提交”策略，降低误识别直接触发副作用。
3. 将长对话摘要和 Task Journal 分开，分别维护对话记忆与任务状态。
4. 增加音频设备切换、断线、回放打断和长时通话的真实测试矩阵。
5. 对不可逆动作使用可视化审批，而不是只靠语音“确认”。
