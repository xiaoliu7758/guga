# 咕嘎立体动作升级 v2

> 当前状态：用户反馈侧背壳破坏原图观感后，已恢复原版贴图。此页保留为开发实验记录；3D 普通菜单入口与自动演示均已停用。

本轮固定现有建模和贴图，升级动作控制器与渲染变换。原 `guga.blend`、`guga.glb`、`avatar.mesh.json.gz` 的 SHA-256 均与修改前一致。

## 怎么看效果

右键咕嘎 → **音乐与动作 → 立体动作演示（15 秒，结束后恢复）**。

演示会临时启用现有 3D 模型，依次转圈、探头、挥手、戴墨镜跳舞，结束后恢复原来的形象与音乐动作状态。若在演示中手动切换形象，会取消剩余演示回调，尊重手动选择。

原画模式继续保留。需要持续使用模型动作时，在“形象”菜单选择“原画曲面 3D · 预览”。语音、音乐事件和原有动作工具继续接到同一套接口。独立动作演示不打开麦克风、不调用模型、不播放歌曲。

## 改了什么

| 动作要素 | 实现与可见效果 |
|---|---|
| 转身惯性 | 根据身体转向角速度计算头部延迟，使用阻尼弹簧回中；360° 结束用角度环绕处理，防止突然反转 |
| 身体体积运动 | 增加俯仰角与前后位移；保留正面原图比例，移动时用弱透视产生近大远小 |
| 探头 | 身体前倾、靠近、侧移，头部反向补偿，结束后收回 |
| 翅膀 | 不仅沿画面左右摆动，还绕前后、内外方向转动，挥手有空间轨迹 |
| 双脚 | 按节拍交替抬起、脚尖俯仰、脚掌转向，跳跃时有离地姿态 |
| 金属扣 | 对现有链扣网格施加独立摆动，随身体倾斜延迟并回弹；不重新建模 |
| 动作衔接 | 跳舞渐入/渐出，松开拖动后抬升量逐渐归位 |
| 接触影子 | 跟随重心偏移，跳起时扩大并变淡，避免像整张图片悬空平移 |
| 取景 | 挥手/舞蹈时平滑留出额外空间，防止翅膀被窗口裁掉；桌宠窗口和气泡位置不变 |
| 语音反馈 | 继续接收原有说话幅度，增加轻微头部节奏；没有宣称新增精确音素口型 |

这些动作在本地计算，不要求大模型持续生成动画帧。当前头部仍是原画曲面模型，本轮没有改变其造型或侧背部结构；头发尚未拆成独立发束，不宣称已有真实发丝碰撞模拟。

## Blender 动作文件

`runtime/motion-v2/guga-actions-v2.blend` 是从已认可的模型**另存出的动作工作副本**，默认选中舞蹈动作，可在 Blender 时间轴播放。原模型文件不覆盖。

`runtime/motion-v2/guga-actions-v2.glb` 包含七套动作：idle、spin、sneak_peek、wave、dance、bounce、nod。导出器在副本中给链扣添加附挂骨骼，并验证原网格顶点和面索引未改变。运行时继续读取原模型资源，由 `AvatarMotion` 实时驱动，不必启动 Blender。

```powershell
& 'G:\GameDev\Tools\blender-4.2.9-windows-x64\blender.exe' -b --python tools\export_blender_motions.py
```

`framing` 是桌面取景参数，不作为 Blender 的角色骨骼缩放烘焙；这样 Blender 动作不会混入 UI 留白处理。

## 有限验证

- 9 项动作测试和 8 项原音乐测试通过，共 17 项。
- 100% / 200% DPI：四套主要动作共 732 帧真实 OpenGL 渲染，逐帧检查裁切与透明度。
- 去掉前后/脚部/翅膀的空间通道后，渲染像素确实发生变化，验证参数已接到渲染层。
- 本机渲染中位数约 2.2～3.3 ms / 帧，目标 30 FPS。这是短时测量，不代表所有机器的性能。
- Qt 集成验证：切换形象、隐藏后端停止、唱歌状态、故障回退、演示自动恢复、手动取消演示通过；菜单两次约 39 ms / 4 ms。
- 原长语音气泡与本地任务入口的离线冒烟检查通过，本轮未拨打在线语音或使用 API 额度。
- Blender 动作副本包含七套动画；模型源文件哈希与副本网格哈希检查通过。
