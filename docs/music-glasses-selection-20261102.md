# 唱歌墨镜与真实选词触发

## 唱歌墨镜

实际音频播放器进入 PlayingState 后，咕嘎与当前陪伴角色进入唱歌舞台：开始摇摆并持续戴墨镜。墨镜状态由独立的音乐舞台标记锁定，普通动作、移除墨镜动作和 8 秒定时都不会在播放期间摘掉；只有真实音频停止、暂停后按现有互动逻辑退出或播放失败时才释放。

播放器每 250ms 只比较一次本地播放状态，并在状态变化时补发舞台事件，防止窗口重载或漏接信号导致“音乐在播、墨镜却没戴”。该同步不调用模型、不录音、不访问网络。

## 划词触发

左键手势仅是一个候选信号。现在必须先通过 Windows UI Automation 确认：

- 目标软件确实产生了非空文字选区；
- 选区有有效像素矩形；
- 鼠标松开位置落在该选区矩形附近。

只有三项都成立才截取局部画面并显示「解释 / 截图分析」；普通空白拖拽、桌面划动、旧选区和没有文字区域的拖拽都不截屏、不弹条、不调用模型。点「截图分析」会使用选词时的局部缓存画面；解释也使用该高亮选区画面，避免把相邻未选文字当成目标。

本轮将原有“先截屏、后检查文字”改为“先检查文字和几何、再截屏”。当前运行版已把划词开关重新开启。

## 验证

- 针对性单测通过：文字+覆盖几何才触发；空文字和旧几何不截图；解释与截图分析都可用缓存选区；唱歌墨镜跨长时动作保持；播放器状态补发只发一次。
- 语法检查与 Git whitespace 检查通过。
- 全部 96 项相关离线回归通过。
- 运行版重启后 `selection_toolbar_enabled=true`、`selection_hook_active=true`，触发策略为 `uia_text_geometry_before_capture`。真实外部选词界面验证受当前鼠标键盘占用打断，代码路径由离屏回归覆盖。
