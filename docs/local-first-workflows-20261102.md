# 本地优先任务路由与可记忆工作流

版本：`2026-11-02.local-first.4`。

## 调查结论

此前所谓“概率模型分流”确实只存在于 `tools/run_ollaya_shadow_test.py`，用于离线影子测试；实际执行入口的 `use_dsh()` 直接返回 DSH。当前本机 `127.0.0.1:11435` 没有运行，因此不能把生产路由建立在这个服务上。

微信能力也一直没有删除：`WeChatAgent`、搜索会话、核对标题、输入正文、点击发送和发送后回读都还在。回归原因是路由把“给微信小军发自我介绍”判为 DSH，而 DSH 没有进入原来的本地微信快捷链。

## 新执行顺序

1. 本地确定性命令：打开浏览器、网页、歌曲、动作等，零模型往返。
2. 已保存工作流：按明确触发词命中，交给咕嘎本地视觉/UIA 智能体执行。
3. 咕嘎本地智能体：微信、常用软件、截图、识屏、网页和一般多步桌面操作。
4. DSH：只处理明确代码、源码、项目、多文件、编译、重构和工程测试；用户可手动强制 DSH。
5. 本地任务失败后保留现场与检查点，由用户决定是否升级 DSH，避免自动重放已经发生的点击或发送。

本地概率模型保留为长而含糊请求的可选建议源，默认超时 350 ms 且失败后离线缓存 30 秒；短请求、截图任务和已保存工作流不会等待它。

## 用户可定义工作流

在咕嘎对话里发送：

```text
定义工作流：整理下载文件夹 | 先观察目录，按扩展名分类，移动后重新列表核验
查看工作流
启用工作流 custom-xxxx
停用工作流 custom-xxxx
切换到自动执行器
```

工作流保存在 `runtime/chat/workflows.sqlite3`，包含步骤、状态、成功/失败次数和最近结果。执行成功会累计记录；同一目标连续成功两次后会形成 `candidate` 候选。候选不会自动获得操作权限，必须明确说“启用工作流”后才进入快速匹配。

## 内置：腾讯会议录制到 B 站

触发说法包括“把最新会议录制上传 B 站”。执行顺序：

1. 打开腾讯会议，按时间选择最新一场真实会议录制，跳过 WorkBuddy 等非会议录屏。
2. 通过浏览器打开录制并使用“另存为/下载到本地”。
3. 核对真实视频文件、字幕和时长。
4. 处理底部时间进度条和中文字幕。
5. 打开 B 站视频投稿页，上传成片，标题固定为“AI 全栈开发系列”，简介按视频实际内容生成。
6. 上传完成、回读标题/封面/简介和可见度后暂停；点击发布前再做一次明确确认。
