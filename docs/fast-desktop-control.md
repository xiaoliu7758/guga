# 更快的桌面控制与内存边界

## 当前执行优先级

1. **UIAutomation 结构化控件**：读取控件名称、AutomationId、ControlType，优先使用 `InvokePattern`、`ValuePattern` 或 `SetFocus`。这条路径不需要每步截图，也不需要视觉模型猜坐标。
2. **已观察窗口的键盘和鼠标**：只能在最近 30 秒的截图观察 ID 和前台窗口未变化时发送；输入后必须重新观察。
3. **视觉模型定位**：UIA 无法识别自绘控件、画布或游戏画面时才使用。

`core/uia_service.py` 在常驻的独立 MTA 子进程内通过 pythonnet 加载 Windows UIAutomation，使慢控件不能卡住 Qt 收音与对话线程。明确名称、AutomationId、类型时执行原生条件查询；需要整页认识时才广度优先遍历。属性批量缓存，返回稳定 `ref`、控件类型、Pattern 和区域。`computer(action=uia)` 支持 `ref`、`invoke`、`set_value`、`focus`；`uia_read` 定向读取目标；`uia_wait` 定向等待出现或 enabled/offscreen 变化。控件没有可调用 Pattern 时才回退中心点击；已经尝试的 Pattern 出错时不自动换另一种动作。

控件引用在 30 秒内复用，并在发送动作前更新和核对。重名目标拒绝猜第一个。`set_value` 精确回读内容、`focus` 回读焦点成功后返回 `verified=True`，无需再经模型截图确认同一个动作；点击和提交只表示动作已发送，仍需定向核对业务结果。普通调用上限 2.5 秒，初始化 4 秒；等待按指定时限，最长 32 秒。超时停止对应 UIA 子进程并报告结果不确定，不自动重放。仅底层 UIA 依赖不可用时保留原 PowerShell 兼容路径。

浏览器长语音单步操作直接走本地执行器，成功即时气泡反馈并继续听下一句；不再每步追加确认音频。详细指令、实测和范围见 [浏览器响应修复与验收](browser-response-20261104.md)。

2026-10-21 本机实测：桌面控件视图截取 30 个节点约 0.33 秒；临时记事本窗口截取 57 个节点约 0.79 秒，识别到 MenuBar、MenuItem、Document、Button、List、Tab 等控件。该结果证明读取链路可用，尚未证明任意应用的 Invoke/Value Pattern 都完整实现。

## 为什么不把所有软件都改成直接写内存

普通软件没有稳定的公开对象布局；版本更新后，偏移、对象关系和线程同步都可能改变。直接写内存需要同时知道目标版本、对象地址、生命周期和写入后界面状态，错误不会自然表现为“失败”，而可能静默破坏数据。UIA 是 Windows 提供的正式可访问性接口，通常更快也更稳定。

## 炉石的特殊路径

- HearthMirror 通过反射读取当前棋盘、卡牌 ID、实体 ID 和位置，属于只读集成。
- `memory_execution_available` 仍为 false；没有把读取能力包装成“已经能写内存执行”。
- 要实现直接动作，需要针对固定客户端构建版本验证对象地址、调用入口、参数和回执，并且每个动作都要有日志确认。
- 当前更可靠的路径仍是 Power.log 产生合法候选，视觉定位坐标，窗口输入，最后由日志 `SendOption` + 状态变化确认。

速度优化的优先级是：缓存 UIA 控件、减少不必要的截图和模型轮次、把只读观察批量合并、同一窗口保持焦点；只有在获得明确版本绑定和可验证回执后，才增加受控内存执行适配器。
