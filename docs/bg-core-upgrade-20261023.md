# 独立战棋核心：并行升级阶段结果

时间：2026-10-23。工作范围为独立战棋核心、离线引擎和相关测试，未修改咕嘎语音/UI。本轮没有发送真实游戏输入、写入游戏内存或调用付费模型 API。

## 实时数据与决策可靠性

- `LiveReader` 增加最近一局启动方式：最多向后扫描 64 MiB，按块寻找 canonical CREATE_GAME，再增量读取。没有找到时仍完整重放，不以残缺日志构造棋盘。
- 恢复 CREATE_GAME 前的本地玩家映射，防止漏掉以玩家名记录的金币消耗、淘汰等标签。映射仅驻内存，不写进诊断结果。
- 真实约 77 MB 日志的稳定输入比对：完整重放约 3008 ms，最近一局约 1035 ms，约 2.91 倍；两种方式的实体、选项、目标、局起点和构建号完全一致。空闲增量读取约 0.1 ms。这是数据读取时间，不是下棋动作延迟。证据见 `runtime/bg-reader-benchmark-20261023.json`。
- 局面目标和选项改为独立副本，后续增量事件不再修改已经用于决策的快照。
- 清理不在当前选项/目标中的历史商店辅助按钮，缩小模型上下文。
- 升本费用优先读取明确的费用标签，再取当前升本按钮 COST；未知费用不再视为免费，明确的 0 费用保留。
- 圣盾、嘲讽、复生、风怒等效果和费用变化会使旧局面标识失效；这些已观测关键词也进入模型局面。
- 出牌成功要求请求站位、发送记录站位和最终 ZONE_POSITION 一致。实体从过滤后快照中消失不再被当成冻结成功。
- 旧观察/训练入口默认引擎从旧实验室路径改为 `runtime/bg-engine-current`。
