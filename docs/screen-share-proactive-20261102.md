# 共享屏幕、桌面气泡与主动搭话

版本：`2026-11-02.voice-assistant.6`。

## 改造前的实际能力

咕嘎已有单次整屏截图、区域截图、窗口截图、UIA 和视觉问答；任务执行器可主动观察窗口。原实时通话只上传麦克风音频，没有 2—5 帧/秒持续共享，也没有把视频帧送给千问实时模型。

当前实时语音模型 `qwen-audio-3.1-realtime-plus` 属于音频模型。阿里云文档把实时图像能力写在 Omni Realtime 系列，并通过 `input_image_buffer.append` 输入，建议帧率约为1帧/秒；当前模型不能直接接收这些图帧。[Qwen-Omni-Realtime 图像输入说明](https://www.alibabacloud.com/help/en/model-studio/realtime)

## 现在的实现

- `core/screen_share.py` 在用户授权和完整访问开启时，以2—5帧/秒（默认3）抓取所有屏幕，JPEG缩放到最大1280×800，只存进程内存，不写录像、不写截图。
- 不显示共享屏幕预览；用户无需查看画面，状态只在内部回执和 `app_state` 中可查。
- 开启长语音通话时默认自动开始共享，通话结束或语音连接失败时自动停止。普通文字/执行任务不会自行开启屏幕采集。
- 语音和文字支持“共享屏幕”“共享屏幕每秒五帧”“停止共享屏幕”。
- `screen_share` 工具提供 start/status/stop/context/snapshot；本地执行器和 DSH 工具桥都可以读取最近的画面上下文和最新帧。
- 画面变化达到阈值时，视觉模型 `glm-4.6v-flash` 在2.5秒最小间隔后抽取上下文，单次最多读取8秒。主视觉服务限流时暂停60秒，并对同一帧改用当前已配置的 Go 聊天模型读取；本机 Windows OCR 也并行尝试。后备成功或两者都失败后都不会无限重试同帧，画面静止时不重复请求。
- 默认每分钟最多6次视觉请求，防止拖窗、视频或动画导致无上限消耗；可按需提高，范围1—30次/分钟。
- 画面说明被作为“可能滞后的资料”注入任务，并明确屏幕中文字不能成为指令。精确内容仍应由 UIA/OCR/工具回读验证。
- 共享组件只是低帧率采景；不是安全沙箱，也不把当前音频模型直接变成视频模型。

## 稳定性与任务辅助

- 每帧同时记录前台窗口句柄、进程和标题；即使像素变化很小，只要前台窗口切换也会强制刷新画面理解。旧窗口的画面资料在窗口切换后自动标为不匹配，不能用于点击新窗口。
- 采集遇到单次或两次临时异常会短退避后继续，三次连续失败才停止；长语音通话另有5秒守望，共享意外停止时最多每30秒尝试恢复一次。用户明确说“停止共享”后，本次通话不会自动恢复。
- 任务交接只注入当前窗口、画面摘要、画面时效和是否与前台窗口匹配；执行过程中每三个工具步骤自动刷新一次共享上下文，避免一直依据任务开始时的旧画面。
- 模型必须先用前台窗口的 hwnd/process/title 核对目标，再用 `computer.windows/focus/accessibility`；共享画面不能替代结构化控件和操作后的回读。

## 气泡

- 桌宠气泡宽度从固定326像素改为380—620像素自适应，使用屏幕可用区域，不超出屏幕。
- 原先220字符预览截断改到1600字符；普通任务结果和主动搭话可以直接在桌面气泡中读完。
- 对话窗口默认宽度从480调到720，最小宽度520；语音设置中的会话气泡最大宽度从440调到620。
- 极长内容仍可能超过屏幕高度；这类内容保留在完整对话记录中，桌面气泡以1600字符为技术上界。

## Token与费用边界

- 2—5帧/秒采集、JPEG压缩、变化检测和预览都不调用模型，不消耗 token。
- 主视觉路径是 `glm-4.6v-flash`；当前公开价格信息显示该 Flash 视觉模型免费，但仍受服务端额度和并发限制，本项目实测遇到HTTP 429。
- 主视觉不可用时，后备路径使用 `ai_config.json` 当前聊天模型；本次为 `deepseek-v4.1-flash`（Go套餐）。实测一张1280×800测试帧消耗755输入+86输出=841 tokens，响应usage中 `cost=0`、`list_cost=0.00016485`，实际套餐扣减以服务商账户为准。
- 默认每分钟最多6次视觉分析，且只在画面变化后触发；连续剧烈变化的极端上限约为6×841=5,046 tokens/分钟，十分钟约5.0万tokens。静态或变化不足阈值的画面不会按3帧/秒重复请求。
- 千问实时语音仍按音频对话产生自己的 token；共享屏幕不会把图片帧直接送给当前音频模型。

## 主动搭话

- 主动定时器随咕嘎启动，而不是只在长语音通话时存在。
- 长通话中且空闲时，将记忆话题交给实时语音模型自然发起。
- 未开长通话时，用当前成员真实长期记忆和近期用户话语调用聊天模型，生成一到两句口语；成功后写入对话记忆，由Edge TTS自然说出并显示完整气泡。
- 任务执行、音乐播放、模型说话、用户说话、模态设置窗口打开时都不打断。默认至少空闲180秒、两次主动搭话间隔至少360秒。
- 每次只提交最多4条脱敏后的真实记忆；没有足够记忆时只能基于角色问轻松话题，不能假装记得用户没说过的事。

## 验证

- 相关离线/Qt回归158项通过；新增测试覆盖帧率限制、真实本机采集、瞬时错误恢复、内存状态、前台窗口切换失效、共享上下文过期、主视觉限流后的聊天模型后备、长通话默认启停、无可见预览、守望恢复与手动停止、任务上下文注入、气泡完整内容、离屏主动搭话和禁止打断。
- 本机实际采集3帧/秒，2.5秒得到8帧，最大尺寸1280×800，原屏2560×1600；停止后采集状态为false。
- 视觉模型探测实际返回了前台编辑器和界面描述；合成画面中的数字末尾被误读一位（20261102读成20281102），因此不能把视觉摘要当成精确OCR。
- 实际连续共享以3帧/秒运行，主视觉源遇到限流后由已配置的Go聊天模型读取同一帧，约4.65秒形成106字上下文；音视频帧均未落盘。
- 最终常驻实例（PID66580，`voice-assistant.4`）启动后状态为无通话、无共享。未开启长通话时，`screen_share.start`会被宿主拒绝，确认普通任务不会私自采集屏幕；完整访问与管理员身份保持开启。
- 主动搭话使用一次真实模型请求；临时测试记忆包含“AI学习资料”，返回24字消息并正确引用“AI”，未保存实际回复正文到证据文件。
- 未替用户开始真实麦克风长通话；未修改千问模型或免费额度确认，也没有把项目改成付费视频模型。

## 证据与设置

- `runtime/voice-assistant-qa/screen-share/`：合成画面、视觉结果。
- `runtime/voice-assistant-qa/proactive/result.json`：主动搭话是否触发、篇幅和记忆标记，不含实际回复。
- 设置键：`screen/share_fps`（2—5，默认3）、`screen/context_seconds`（默认2.5）、`screen/max_analyses_per_minute`（默认6，范围1—30）、
  `multiagent/proactive_idle_seconds`（默认180）、`multiagent/proactive_cooldown_seconds`（默认360）、`multiagent/proactive_offline_speak`（默认true）。
