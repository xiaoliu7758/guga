# 咕嘎与 DSH 的实际连接审计

日期：2026-11-02。范围：源码、当前运行实例只读状态、淋雨家工作台公开源码；未修改运行逻辑，未调用付费模型，未重启应用。

## 结论

咕嘎目前的主任务引擎是自己的 SelfAgent。DSH 是可选、按任务启动的独立执行器。称为“DSH 已接入”符合源码；称为“整个咕嘎已由 DSH 驱动”不符合现状。

## 本次实证

- 通过现有本机命名管道读取运行中咕嘎的 app_state，成功返回：dsh.running=false、last_phase=null、recent 事件数为 0。这说明当前实例的管理器没有记录到 DSH 任务，不代表所有历史版本从未调用过。
- 咕嘎当前 full_access=true，但 Windows administrator=false。应用内完整访问开关不会自动赋予 Windows 管理员权限。
- 另有独立启动器运行 DSH Web 服务，其进程参数为 web --no-open；本次核对的咕嘎 DshManager 通过启动 headless 子进程通信，没有连接该 Web 服务。
- 本机安装包 package.json 显示 @deepseek-ai/dsh 版本为 0.2.1-rc.5。仅核对本机安装版本，不据此宣称远端最新。

## 真实调用链

1. ui/agent_chat.py 创建 SelfAgent。
2. core/self_agent.py 向 DeepSeek 提供工具列表，其中包括 dsh_task。提示词写的是复杂任务“可交给”，并非强制路由条件。
3. 模型选用 dsh_task(start) 时，ui/agent_runtime.py 调用 DshManager.start，传入任务、会话、目录、预算、成员身份及最多六条相关记忆。
4. core/dsh_worker.py 才真正启动进程：源码态调用 dsh --profile headless --json -；打包态使用内置 node.exe 和 DSH CLI。
5. 任务文本通过 stdin 写入；stdout 逐行读取 JSON 事件。Windows CREATE_NO_WINDOW 隐藏终端窗口。
6. session/status/final 等事件返回咕嘎，ui/agent_chat.py 更新状态、气泡、对话与语音通知。最终结果明确标记尚未独立核验。
7. 支持已有 session_id 续接，但当前入口没有强制为每个项目自动保存并恢复固定 DSH 会话。

安装 DSH、启动 DSH Web、模型实际调用 dsh_task，是三个不同事实。没有可见窗口并不能证明没运行；安装成功也不能证明某条任务经过了它。

## 能力边界

- DSH 使用自己的工具与配置。当前交接不会自动复制咕嘎的 Python 工具列表。
- core/mcp_contract.py 的 self_tools 只向外声明 app_state、pet_control、workspace、applications 四类工具。
- tools/guga_mcp_server.py 和 ui/mcp_bridge.py 都校验这个列表；不能把 SelfAgent 内部的全部能力说成已通过 MCP 共享。
- DSH 如配置了自己的命令或浏览器工具，可以使用那些工具；这与调用咕嘎已经调好的微信、截图、UIA、搜索专项执行器是两回事。
- 目前缺少明确的任务执行器展示、自动路由记录、完整共享工具清单，以及独立结果验收闭环。

## 建议架构：操作系统助手与受控改进

用户语音 → 咕嘎交互与任务调度

- 明确的短指令 → 现有本地快捷执行器。
- 需要多步规划的任务 → DSH 专业执行器，保留 SelfAgent 回退路径。
- 两种执行器 → 同一组已验证的桌面、浏览器、文件、微信工具和目标绑定规则。
- 工具真实结果 → 独立验收 → 任务档案 → 咕嘎汇报。
- 失败和成功案例 → 候选技能 → 隔离回归 → 达标后激活 → 可回滚。

这里的自我改进首先是改进工具、流程、提示和记忆，不等于训练模型权重，也不等于自动取得更高系统权限。

## 实施顺序与验收

以下均是建议，尚未在本次调研中实现。

1. **先可见**：每个任务展示实际执行器、运行状态、最近工具与最终证据；只有真的创建 DSH 任务才显示 DSH 执行中。
2. **再打通工具**：优先桥接只读观察、文件、浏览器，再接已调好的桌面专项工具。保持用户已有授权，不因工具换了执行器就扩大权限范围。
3. **再稳定路由**：短指令继续快速执行，多步任务明确交接；保留任务身份、续接信息和停止入口，避免两套执行器同时控制同一桌面。
4. **最后做进化闭环**：在候选目录生成变更，通过固定任务集检验成功率、耗时和误操作，达标才激活，失败回滚。

最小验收例：语音交办“搜索三个来源、写成文件并打开”。能看到实际 DSH 任务和工具事件，文件落盘并被回读，浏览器或编辑器打开目标，咕嘎最后依据证据汇报；中途停止可以阻止后续操作。单独出现一段 DSH 回答不算完整验收。
