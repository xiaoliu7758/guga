# 咕嘎怎样升级成电脑管家（2026-10-29）

## 今天查到的实际状态

对运行中的咕嘎读取状态，确认「完整访问」已打开，进程确实是管理员。启动配置没有要求每次自动提权，所以换一种启动方式时，身份可能不同。本轮悬浮窗升级重启时已经保留管理员身份。

配置中的任务大脑为 deepseek-v4.1-flash；实时通话为 qwen-audio-3.1-realtime-plus。普通短命令可以由本地直接执行，较复杂的问题和操作交给 DeepSeek。模型在远端理解任务，本机程序负责动鼠标、输入、打开软件和改文件。

现有四种做事方式：

1. 直接告诉 Windows 打开某个软件或网址。打开请求发出了，还要检查软件是否真的出现。
2. 向软件索取按钮清单，找到「搜索」「发送」这些控件，让它们执行操作。这就是当前 UIA 路线的大白话含义。
3. 软件不给按钮清单时，按需截一张图，再模拟鼠标键盘操作。现有代码不是持续视频共享。
4. 直接读写文件、执行命令；多阶段长任务也可以交给独立的 DSH 程序，结果传回咕嘎。

管理员表示能够做更多系统操作，但不会让模型自动知道每个软件的用法。它也不等于 Windows 自身的 SYSTEM 身份。当前通用软件操作不依靠随意改写软件内存；读按钮、用软件提供的入口、执行命令，已经能覆盖大量任务。[Windows 输入权限说明](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-sendinput)、[SYSTEM 账号说明](https://learn.microsoft.com/en-us/windows/win32/services/localsystem-account)。

## 当前最值得补的地方

现有脚本、通用操作能力、完成记录都已经有了。源码仍有固定步数、单条命令时间以及长任务时间限制；复杂任务要有保存进度、续做和停止规则。这里是产品内部的任务设置，与用户已取消的 Codex 20 分钟工作限制无关。

通用收尾已经会检查工具回执和操作后的观察，但「看过一个截图」与「确实完成了用户目标」还有距离。应该逐个任务明确验收：网页实际打开到哪里，信息是否出现在正确聊天里，文件是否保存到指定目录。

我建议优先建立：软件和窗口现状、最合适的做事办法、失败后的备用办法、结果核对、重启后继续、做成功的方法复用。现有权限已经够开展这些工作。

## 可以借鉴的开源项目

| 项目 | 大白话 | 对咕嘎的价值 |
|---|---|---|
| [微软 UFO](https://github.com/microsoft/UFO/tree/main/ufo) | 总管拆任务，各个助手熟悉不同软件；有直接入口就用入口，再考虑点击 | 最贴近 Windows 电脑管家的总体组织方式 |
| [Windows-MCP](https://github.com/CursorTouch/Windows-MCP) | 给大模型提供一套 Windows 操作工具 | 学习按钮读取、操作工具、超时处理；与咕嘎现有 UIA 同类，不代表装上就万能 |
| [Browser Use](https://github.com/browser-use/browser-use) | 专门熟悉网页的助手 | 把网页任务交给懂页面结构的工具；能否直接接当前豆包浏览器仍需另测 |
| [Agent TARS / UI-TARS Desktop](https://github.com/bytedance/UI-TARS-desktop) | 综合使用画面、网页内容和其他工具完成任务 | 学习看图兜底、执行过程展示与工具组合 |
| [Agent S4](https://github.com/simular-ai/Agent-S/tree/main/agent_s4) | 分析做任务的经历，改进供助手使用的小工具，再用另外的任务检验效果 | 学习「越做越熟练」；重点是改进方法和工具，不能直接说成模型已经训练变强 |
| [Hermes Agent](https://github.com/NousResearch/hermes-agent) | 记住经验，积累技能，下次继续使用 | 学习长期任务、经验整理和跨会话继续工作 |
| [OpenClaw](https://github.com/openclaw/openclaw) | 将聊天入口、任务、工具、记忆交给一个常驻的总管 | 学习咕嘎作为外壳、执行系统独立运行的组织方式 |

以上核对的是公开项目文档，没有在本机逐一安装和验证。像 UFO 文档里仍标为未来功能的独立操作桌面，不能当作现成功能承诺。各项目依赖、模型适配和权限方式需要独立测试，不能整包混进现有咕嘎。

## 建议的升级次序

第一步把三个最常用任务练稳：打开网站并搜索、微信找到对象后发送、按指定目录整理文件。软件已开/未开、最小化、网络失败，都要测。验收看结果，不听口头宣称。

第二步让咕嘎会选办法：文件任务直接处理文件，网页任务使用网页专用能力，普通软件读按钮，最后再用看图点击。已验证的操作可以连续完成，关键位置复查，减少每点一次都问模型。

第三步加一本经验册：记录某个任务成功需要什么条件、怎么做、怎样确认；界面变了就重新核对。试验出来的新办法先在副本测试，通过后再替换旧办法。先做到方法复用，再考虑耗时更大的模型训练。

第四步逐步支持常驻提醒、事件触发和任务恢复。它知道自己正在做什么、你当前在哪个软件、什么时候应该停下来让你用电脑。真正的电脑管家需要把这些日常细节做稳。
