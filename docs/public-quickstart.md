# 咕嘎桌宠公开版快速开始

当前版本包含实时语音、通用桌面工具、可恢复长任务、头顶气泡、HearthMirror 只读棋盘和战棋离线实验室。下载后需要填写自己的模型 API 配置；仓库不包含任何 API Key。

## 1. 安装环境

- Windows 10/11。
- Python 3.10 或更高版本，推荐 3.12。
- 支持麦克风的输入设备和支持关闭回声的耳机或扬声器。

在项目目录运行：

```powershell
python -m pip install -r requirements.txt
```

下载后也可以直接双击 `启动企鹅.bat`，它会在缺少 PyQt5 或 edge-tts 时尝试安装依赖。

## 2. 配置两条模型链路

双击 `首次配置.bat`。脚本只在 `ai_config.json` 不存在时复制模板并打开记事本，不会覆盖已有配置。

实时语音默认关闭声纹匹配，无需录入主人声音，麦克风直接进入实时语音链路。如以后手动启用可选声纹门禁，再运行 `录入主人声音.bat`；该模式会拦截未通过匹配的语音。

### 聊天与任务模型

填写 OpenAI Chat Completions 兼容接口：

```json
{
  "api_key": "YOUR_CHAT_API_KEY",
  "base_url": "https://YOUR_OPENAI_COMPATIBLE_ENDPOINT/v1",
  "model": "YOUR_CHAT_MODEL_ID"
}
```

该模型负责任务规划、工具调用、文件/桌面操作和最终回答。视觉控制还需要兼容图片输入的多模态模型；如果只使用 UIAutomation 结构化控件，可以不依赖截图视觉模型。

### 端到端实时语音

填写千问 AI 平台的实时语音配置：

```json
{
  "realtime_voice": {
    "provider": "qianwen",
    "model": "qwen-audio-3.1-realtime-plus",
    "api_key": "YOUR_REALTIME_VOICE_API_KEY",
    "voice": "longanqian_v3.1",
    "free_only": true
  }
}
```

实时语音负责麦克风收音、轮次检测、自然语音和打断；聊天模型负责真正的任务与工具调用。两边的 Key 分开填写，不要混用。

使用免费额度时，先到千问平台权益页为**完全相同的模型 ID**开启“免费额度用尽即停”，再在咕嘎的“实时语音配置”中确认平台和模型。程序无法代替平台侧开关；未确认时不会联网。使用付费额度时，需要自行确认所选模型权限和计费方式。

### 可选视觉模型

桌面截图定位和战棋看画面使用 `zhipu_api_key` / `vision_model`。只做文本任务和 UIA 控件操作时可以不填。模型名称与权限以对应平台文档为准。

## 3. 启动

双击 `启动企鹅.bat`。脚本会请求管理员权限；本机授权和系统权限策略决定实际能操作哪些软件。授权模式继承咕嘎 Python 进程的 Windows 权限。

启动后：

1. 右键桌宠 → `对话 · 咕嘎智能体`。
2. 打开 `软件权限`，确认完整访问范围。
3. 点击 `语音对话`，允许麦克风。
4. 直接说任务，例如“打开记事本，读取当前窗口，输入一段中文，再检查输入是否成功”。

“打开某网页”“打开记事本”“搜索某内容”“停止对话”等低歧义命令会走本地快速路由，不进入 DeepSeek，也不生成 TTS 回复。复杂多步任务才会使用聊天模型或 DSH sidecar。

## 4. 安全与数据

- `ai_config.json`、`runtime/chat/`、`runtime/agent-tasks/`、任务命令输出和战棋审计均被 Git 忽略。
- 工具输出中常见密钥字段会脱敏，截图不写入任务日志。
- 所有模型操作都应经过工具执行和结果回执。当前新增完成门槛：未复查的桌面输入或失败副作用不会显示为“已完成”。
- 打开第三方软件只代表 Windows 接受启动请求；是否成功打开、是否完成软件内部动作，以窗口和工具回执为准。

## 5. 常见问题

**语音按钮提示配置未确认**：检查 `provider`、`model` 与平台权益页是否完全一致，并确认免费额度用尽即停。

**模型返回 HTTP 401/403**：检查聊天和实时语音是否分别使用正确的 Key、接口地址和模型 ID。

**能对话但不能看屏幕**：当前聊天模型可能不支持图片输入，或未配置视觉模型。可先使用 `computer.accessibility` / `computer.uia` 走结构化控件路径。

**管理员程序无法被普通权限咕嘎操作**：用同一管理员权限启动咕嘎；操作系统不会允许低权限进程向高权限窗口发送输入。

**声纹总是拒绝主人**：在语音配置关闭“启用声纹门禁”后重新开启通话，恢复直接收音。默认即为关闭。可选门禁的阈值保存在 `runtime/voice/owner_profile.json`。

**声纹开启后丢字或听不清**：先彻底退出并重新启动咕嘎，让音频链路修复生效。当前版本会在本地暂存句首，积累至少约 0.64 秒有效声音再验证，通过后原样发送一次；句中短暂停顿不会删除句首。非常短的单字、噪音或重叠说话仍可能无法验证。主人门禁按语句验证，停顿约 0.7 秒后重新确认身份；不能把它当作高安全级身份认证或多人声音分离。`runtime/voice/speaker_diagnostics.json` 仅记录匹配分数、阈值、音量、排队和耗时等数值，不保存录音、转写或密钥。处理拥塞或声纹进程出错会明确停止通话，不会静默丢字或绕过主人门禁。

**打开浏览器等简单任务**：支持“帮我打开浏览器”“请帮我打开一下浏览器”“帮我打开百度”等口语。识别出完整指令后直接在本地执行，不调用 DeepSeek。通用“浏览器”会直接启动已安装的 Edge/Chrome 新窗口；“默认浏览器”与指定网站使用 Windows 默认链接处理程序。成功时不额外生成回答；失败时显示气泡和真实原因，不会提前报告成功或反复转交模型。`runtime/voice/fast_command_diagnostics.json` 记录最后一次命令的数值耗时：`asr_after_speech_ms` 是服务器 speech_stopped 事件到完整转写的间隔（不包括此前断句等待，缺失时为 null），`transcript_to_result_ms` 是完整转写到系统启动请求返回的间隔。它们都不是用户说完到窗口显示的完整耗时。当前仍使用自然长对话的智能断句，不靠缩短停顿阈值强行切断长句。

简单命令在文字入口、语音工具委派和原始转写三个入口都会先检查；长任务运行时也立即执行，不排入长任务的追加要求。语音模型先给出改写任务而原始转写稍后才到时，会短暂等待至多 350 毫秒，优先采用本轮原话。没有具体目标的“现在进行测试”不会自动查源码。后台模型在思考或等待工具时保持收音；外放声音实际播放、音频待播和回声尾音期间才抑制收音。每 12 秒的计时信息只显示在界面，避免反复语音播报占用收音时间。通过本机 MCP 的 `app_state.runtime` 可核对 PID、项目目录和 `voice_router_version`；`applications` 的 `command` 操作走与对话相同的本地入口，仅接受已匹配的快速命令。

**DSH 长任务提示 AUTH/401**：DSH 使用自己独立的模型凭据。先运行 `dsh --profile headless --json -` 或通过 DSH 配置/登录修复凭据；不要把私钥写进项目。咕嘎只负责启动 sidecar 并显示事件。
