# 浏览器单步响应修复与验收（2026-11-05）

源码双版本标记：`2026-11-04.browser-response.1`。本次延续长语音稳定性修复，重点是当前网页、用户逐步指挥、简单动作立即执行。GitHub 下载 ZIP 或拉取 main 获取本次源码；历史 EXE 未重新打包。

## 原因与修改

旧底层对按名称定位一个控件仍重新扫描整棵树，逐项跨进程读取属性；等待也反复全树扫描。上层没有直接执行网页单步的入口，简单填写和点击会绕进任务模型，成功后还可能追加模型观察与确认播报。连续合成语音对照中，确认音频占用外放收音门禁，第二句短指令没有被执行；取消成功单步的追加播报后，两句均完成且通话保持连接。这证明该收音问题在本次场景中的因果关系，不推定所有断线都来自同一原因。

现在的链路是完整转写→本地命令匹配→当前浏览器单次动作→即时气泡→继续听。普通文字补充入口复用同一执行器；转写和迟到的原生函数调用共享本轮回执，不重复执行。导航动作及不同字段内容使用不同去重键。

- 精确 UIA 条件查询与批量属性缓存替代每步全树遍历；已有引用复用，发送前重新核对。页面输入框只在网页 Document 内选择，避免把浏览器地址栏当成搜索框。重复名称和多个输入框拒绝猜测。
- 填写直接调用 `ValuePattern`，最多 150 毫秒有界等待精确内容回读；聚焦回读键盘焦点。已有本地回读证据不再要求重复模型观察。按钮回执只说明已点击，提交业务成功仍需实际结果确认。
- UIA 在独立常驻 MTA 子进程运行，调用有界；慢 provider 超时停止对应子进程，不自动重发可能已经生效的动作。Qt 对话线程继续收音和响应。
- 成功单步不另生成确认音频；失败仍说明原因。操作后的 60 秒暂停主动搭话，每次单步续期，普通语音话题退出，减少连续指挥时的收音争用。
- 只操作当前前台浏览器；不自行建立专用浏览器会话、扩展为规划任务或失败后自动改交模型。用户明确委托完整代办时仍保留原能力。

UIA 缓存与原生查询依据微软的 [UI Automation 属性缓存说明](https://learn.microsoft.com/en-us/dotnet/framework/ui-automation/caching-in-ui-automation-clients)。这里使用正式控件接口，没有增加权限，也没有用任意进程内存写入替代控件语义。

## 用法

切到目标网页，打开长语音后逐句说：

1. “点击输入框”（页面只有一个普通输入框时）；也可“点击验收输入”指定名称。
2. “输入咕嘎”（替换当前字段）；“追加输入最新版本”保留原内容。
3. “点击搜索按钮”或“按回车”。

也支持“清空输入框”“向下滚动”“向上滚动”“返回上一页”“前进一页”“刷新页面”“新建标签页”“下一个标签页”“上一个标签页”“聚焦地址栏”。输入是字面文本，保留标点和大小写，不解释成脚本。密码框不进入这条通用输入路径。没有可访问控件的画布、自绘或远程桌面不能保证相同速度。

## 有界验收

使用独立临时浏览器配置和本机 HTTP 自有测试页；UIA 执行动作，Playwright 读取 DOM、输入值、按钮回调及滚动位置作独立核验。没有操作个人网页或真实表单。Edge 与系统默认豆包浏览器均通过。权限核对显示本次浏览器和桌宠均为普通权限，不存在提权不匹配。

| 场景 | 结果 |
| --- | --- |
| 同一 Edge 测试页，按精确名称填写 3 次 | 修复前 491—517 ms，修复后 23—47 ms；中位数约 508→25 ms |
| 同页控件树读取 3 次 | 修复前 489—604 ms / 127 节点；修复后 156—238 ms / 153 节点 |
| 豆包当前页单步 | 首次点击输入框 98 ms，填写 19 ms，按钮点击 41 ms，DOM 核验通过 |
| 豆包补充滚动核验，与回归并行运行 | 填写 28 ms、按钮点击 57 ms；上下滚动真实位置均变化，16 项检查通过 |
| 连续两句合成语音，真实千问连接 | 完整转写后填写 15 ms、点击 31 ms；0 次任务模型委派、0 次断线，真实输入和按钮回调均正确 |

语音样本运行 17 秒并确认测试线程停止，没有使用麦克风或扬声器。服务端 `speech_stopped` 到完整转写另需 188 / 157 ms，此外还有配置的 600 ms 断句等待。因此 15 / 31 ms 是热态执行延迟，不是从开始说话到网页完成的总延迟。样本不是 P95，页面规模、首次 UIA 初始化、其他系统负载与浏览器实现都会影响速度，不能据此保证任意网页。

335 项相关回归及最后 75 项命令回归通过，覆盖本地单步、歧义和焦点变化、去重、精确查询、超时、结果验证、Qt 不阻塞、语音协议、断线恢复、额度保护、后台任务和普通问答隔离。既有 GIF 资源 `ResourceWarning` 不属于本次失败断言。

从 Git 索引导出的无私人配置源码另通过 43 项核心检查；独立 UIA worker 初始化及关闭成功。1280 个索引文件通过发布范围和凭据扫描，295 个 Python 文件通过语法检查；本机配置、运行记录、战绩改动与私人打包脚本未进入本次提交。源码桌宠已加载双版本标记和单步模式，完整访问开启、普通权限、语音未自动开启。

本机证据在 `runtime/browser-response-qa/`：`before.json`、`live-voice-final.json`、`default-browser-final.json`、`default-browser-scroll-verified.json` 和 `final-regression.txt`。失败对照也保留，不随公开仓库发布。

## 复测

离线核心检查：

```powershell
python -m unittest tools.test_browser_responsiveness tools.test_personal_harness tools.test_long_voice_stability tools.test_realtime_agent tools.test_execution_contract -q
```

本机浏览器检查需要已安装项目依赖及 Edge 或系统默认 Chromium 浏览器，会临时显示自有测试页面，结束即关闭：

```powershell
python tools/probe_browser_responsiveness.py --commands --browser default --label local-browser
```

加入 `--live-voice` 会显式使用当前已确认免费额度进行两句合成语音验收，最长 28 秒采样并关闭连接；不改变额度保护或录制麦克风。调用上限、控件引用与内存边界见 [快速桌面控制](fast-desktop-control.md)。
