# 长任务执行与2026-10-22修复说明

当前分工来自本地源码与配置核对：

- 千问端到端语音模型负责收音、自然语音交流和播报，通过 ask_deepseek 转交任务。
- 普通的打开浏览器等明确短指令走本地 fast_commands，不请求 DS。
- OpenCode Go 官方地址 https://opencode.ai/inference/go/openai/v1 下的 deepseek-v4.1-flash 是内置 SelfAgent 的决策模型；它通过 function calling 选择 computer、local_computer、applications 等工具。Python 执行器真正操作系统，并把结果交回模型。
- 内置 SelfAgent 默认单任务900秒，上限80轮模型调用、160次工具操作；每轮输出按当前 max_tokens 配置为1200，调用代码把上限夹在1200—4000，thinking 明确 disabled。多轮执行不等于开启最高推理档，也不等于每个任务都能成功。
- DSH 是可选的另一条 sidecar 路线，有自己的进程与配置；当前状态没有运行中的 DSH 任务。不能把内置 DS 工具循环等同于 Claude Code 或 DSH。

## 已确认的故障

真实日志在点击输入框成功后，模型继续拿点击前 observation_id 调用 type。执行器为避免过期坐标误操作，在任何输入后立即消耗 ID，导致 type 被拒绝。模型随后反复观察和点击，任务没有完成。

另一个问题是“打开某软件输入……”可能被快速路由当成完整的软件名，未进入 DS 长任务循环。

## 修复

1. 观察ID保持一次使用，提示明确区分“已消耗”和“时间过期”，并说明 observe→type 恢复路径。
2. 新增 computer.fill：在一次观察下完成坐标点击后打字，或 ctrl+l/alt+d 定位地址栏后打字。一次定位最多输入4000字，不自动按回车。过程中前台窗口改变立即停止；保留操作后观察验证要求。
3. 提示模型标准控件优先 UIA set_value，视觉输入优先 fill，避免点击循环。
4. Windows拒绝前台切换时返回可恢复工具错误，避免直接退出整轮；不发送键盘输入。
5. 复合输入/编辑指令不被快速软件启动路由截走；单纯打开浏览器继续走原快捷路径。

## 验证范围

- 74项相关离线测试通过，语音气泡 smoke 通过。
- 真实 OpenCode Go DS 在隔离测试窗口连续填写两个字段并观察复查，实际字段值完全符合，耗时25.8秒。
- 新 fill 在真实隔离窗口输入“咕嘎 typing 123”，通过读取实际输入框内容核对。
- 限制控件树的纯视觉模型测试未取得可靠完成结果，不能将上面的测试当作所有自绘应用/浏览器任务均成功；仍需用户原任务回归。
- 本轮不修改声纹关闭配置、普通Edge TTS或语音收听链路。
