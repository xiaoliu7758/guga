# 长任务通话修复与日常工作流阶段验收

版本：`2026-11-02.daily-workflow.1`。升级前文件备份：`runtime/upgrades/daily-workflow-20261102-133748/`。没有重置其他正在进行的改动，没有更改 API 凭证。

## 这次修复

- 正常执行任务不加载或播放参考视频 `task:*`，保留原画姿态变化。两段用户提供并已指定的待机动画单独保留，不与任务参考素材混用。
- 修复 DSH 返回后 `dsh:<job_id>` 动画状态未结束的问题，避免任务结束仍反复触发动作。
- DSH 内部指令要求在重要阶段完成时发出 `task_report(progress, milestone=true)`；困难和待选择项同样报告，不播报隐藏推理。
- 开启通话时，报告进入现有实时语音连接；不开通话时使用原来的 Edge TTS。不为报告额外建立实时连接。
- 语音播放有有限队列、去重与间隔限制，普通进度至少间隔 60 秒，重要报告至少间隔 10 秒。用户说话打断不会丢弃尚未播报的重要报告；明确取消任务会清除报告。
- 等待用户决定单独记为 `needs_input`，结束本轮，不假报成功，也不继续后续工具。

## 工作流基础

“帮我上传视频”识别为：核实腾讯会议最新录制、合法取得本地视频、理解内容、生成中文字幕及底部时间进度条、准备标题和投稿清单。原视频不覆盖；本轮公开发布前等待用户决定。

视频工具提供检查、抽帧、转写、渲染、查询、取消和准备投稿清单。渲染后台有期限、最多一项并发，任务结束会停止未完成的所属视频作业。当前自动转写使用本地 Vosk，字幕标记为待校对；不能把自动字幕当成已人工审核。

项目验收工作流要求实际测试和截图证据，限定一轮检查及计划交接，不自行无限唤起其他智能体。
