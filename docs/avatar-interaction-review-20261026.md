# 咕嘎形象与交互审核（2026-10-26）

## 本次上线范围

保留 resources/expressions 中的原画，修复表情状态生命周期。没有替换原 PNG，没有启用实验 3D。

- 主人或模型选择的困倦表情持续保持，没有自动恢复倒计时。
- 待机表情、心情刷新、鼠标经过、咕嘎自己说话以及后台提示不能唤醒困倦。
- 主人主动说话（收到非空识别文本）、发送文本、点击或拖动咕嘎、点击对话气泡时，恢复常驻 happy。
- 本轮用户仍要求困倦时，模型可再次调用 set_expression(sleepy)，重新进入保持状态。
- 其他明确指定的表情也不再被待机循环秒恢复；可由模型根据新情境明确切换。
- 端到端语音与内层任务智能体均已提供表情工具；普通无表情标签的文本回复不再强制设置 normal。

实现入口为 ui/sprite_animator.py 的 user_interaction 与 set_expression，ui/pet_window.py 统一收取主人输入，ui/agent_chat.py 连接语音转写和文本发送。

## 验证

- 表情与语音工具、智能体交接、独立关注控制器：28 项离线测试通过。
- 真实 Qt 控件冒烟：困倦保持、主人语音和文本唤醒、语音窗口隐藏、气泡返回同一对话、结束通话、真实本地命令执行通过。
- 原画回归：旧 3D 配置不能覆盖原画，自动演示停用。
- 本机运行核验：已重启为原画模式，困倦经过 3 秒仍保持；再次通过工具请求 happy 被正确拒绝，并返回 applied=false。结束核验时保留困倦，等待主人主动互动唤醒；语音未开启，启动错误日志为空。

上述是离线协议和真实 Qt 控件验证，不代表已对线上语音模型每一轮的表情选择作出保证；实际表情选择仍由模型决定，本地负责执行优先级和保持语义。
