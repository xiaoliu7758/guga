# 本机感知、网页响应与捕获修复（2026-11-05）

源码版本：`2026-11-05.local-eyes.2`。

## 实际问题与改动

- **采集有运行，但感知慢。** 实际长通话中屏幕采集正常，一次云端画面理解约 4.9 秒；网页动效持续使摘要过期，语音收到的 `fresh=false` 不能直接用于回答细节。此前没有把本机 UIA 控件接入这个语音感知入口。
- **日常说法漏过快捷入口。** “你帮我点一下上面的搜索框”“往搜索框里输入……”等未被识别。搜索输入框唯一但名称是内容占位文字时，还会因名称不含“搜索”被错误排除。新增回归在修改前失败，修改后通过；多个输入框依旧需要唯一匹配，不能乱选。
- **短任务反复试探。** 实际网页任务出现过 27 次工具调用、每轮间隔约 3—13 秒及临时 PowerShell UIA 调用错误。短日常桌面任务现在禁用深度思考，最多 4 轮决策、6 次工具、20 秒轮间预算；模型请求读取超时为 12 秒。预算在轮间检查，不是任意工具的硬性总耗时承诺。复杂工程任务保留原预算。已有本地快捷指令绕过任务模型，目标不清时保留真实回执，交回用户逐步指挥。
- **形象被主动排除捕获。** 形象窗口和气泡都曾设置 `WDA_EXCLUDEFROMCAPTURE`（`0x11`），导致遵守此标记的截图、录屏抓不到。现在恢复 `WDA_NONE`（0）；浏览器工具也不再自动隐藏咕嘎。没有改变 Windows 安全或隐私设置。

## 本地“眼睛”如何接入

屏幕共享开启时，独立的只读 UIA 执行器约每秒读取当前前台的可见控件，批量缓存文字、类型、位置和普通输入值；结果只保存在内存。它不占用动作执行器，不在 Qt 或音频回调线程等待 UIA。支持方信息缺失时有限超时、退避重试，停止共享清空结果并回收执行器。

感知资料同时带窗口身份、年龄和来源；切换窗口、超龄及迟到结果不会被当成当前页面。动画造成云端摘要过期时，新鲜的本地文字和控件仍可用。语音 `read_screen` 对文字、按钮、输入框问题直接使用这些事实；图片、颜色和视频内容继续使用实际截图及视觉模型，不把控件文字冒充图像识别。

需要任务模型时，先注入本地控件资料；已有新鲜 UIA 资料的桌面任务不再默认附一张截图增加首轮请求开销。动作仍在执行前重新查询目标，并核对窗口和输入回读，不能直接拿观察缓存当成点击完成证据。

[微软 UIA 缓存文档](https://learn.microsoft.com/en-us/dotnet/framework/ui-automation/caching-in-ui-automation-clients)说明，批量缓存可以减少跨进程取属性的开销。本轮使用的是软件通过 Windows 正式接口提供的结构化对象，不是任意进程地址扫描。工程原有底层内存读取只有炉石专用适配；授予内存读写权限本身不会创建通用软件对象布局。本轮没有声称增加了通用内存写入器。

## 有界验收

自有本机页面使用临时豆包浏览器，由 UIA 执行动作、Playwright 独立核对 DOM。没有提交真实网站表单、联系人消息或账号操作。

| 场景 | 实测结果 |
| --- | --- |
| 本地整页感知，3 次 | 首次连执行器初始化 625 ms；提供方读取 125 / 47 / 47 ms；输入框及按钮均读到 |
| 感知远程模型调用 | 0 次 |
| 自然说法单步 | 聚焦约 24 ms、指定搜索框填写约 36 ms、点击约 25 ms |
| 独立页面核验 | 22 项通过，输入回读和按钮回调正确 |
| 日常模型请求兼容性 | 禁用深度思考后真实服务请求成功，约 4.77 秒返回工具调用；隔离检查没有执行该工具 |
| 形象截图 | 已加载版本的系统捕获标记为 0，独立桌面截图中实际可见形象 |

这些毫秒数是本机已识别单步的执行时间，不是从开口到页面加载结束的总耗时，也不能推广为所有网站的 P95。需要模型理解的未匹配指令仍受模型和网络速度影响；本轮保留了约 4.77 秒的真实模型请求结果，没有把它写成本地毫秒响应。

本轮多次自有测试页因前台切走而按保护规则退出；记录明确显示前台已切到 Typora，未继续发动作，也未进入语音阶段。这些结果保留为未通过。并行语音与本地读取的真实服务样本尚未在固定前台条件下完成，不以之前版本的语音结果代替本轮结果。224 项相关回归通过，覆盖原生 VAD 空档、单线程协议所有权、移除定时主动断开、本地感知隔离、短任务限制与原有 UIA/任务能力。

截图已直接验证。各第三方录屏软件的不同捕获模式尚未逐一测试；取消系统排除标记是本轮确认修复的原因和范围。自绘画布、图片按钮、不可访问控件仍可能需要视觉定位，不能保证任意软件均能通过 UIA 完整读出。

## 复测与本机证据

离线核心检查：

```powershell
python -m unittest tools.test_local_perception tools.test_browser_responsiveness tools.test_personal_harness tools.test_screen_share tools.test_responsive_voice tools.test_voice_call_e2e -q
```

本机浏览器检查会短暂打开临时自有页面；需要保持它在前台，焦点改变即中止：

```powershell
python tools/probe_browser_responsiveness.py --commands --browser default --label local-eyes
```

增加 `--live-voice` 显式使用已确认免费额度测试合成语音，不打开真实麦克风或扬声器。

本机证据位于忽略的 `runtime/local-eyes-qa/` 与 `runtime/browser-response-qa/`：`loaded-capture.json`、`pet-capture.png`、`routine-model.json`、`regression.txt`、`bounded-desktop-regression.txt`、`local-eyes-browser-focused.json`、`local-eyes-voice-final.json`；修改前搜索框及口语失败对照在 `runtime/voice-soak-qa/page-eyes-before.txt`。私人页面、录音、凭据和运行记录不进入公开源码；历史 EXE 未重新打包。
