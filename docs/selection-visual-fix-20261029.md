# 划词解释／翻译重新实现（2026-10-29.4）

## 用户反馈与验收更正

2026-10-29.3 的原生单控件复制测试通过，但用户反馈所有软件里的解释和翻译都失败，提示「未能恢复原选词窗口的焦点」。因此该版没有通过用户场景验收；不能以旧测试结果宣称功能已解决。

这两项功能共用的文字取得路径卡在窗口激活环节，模型还未收到有效选区。上版继续修补焦点恢复没有消除依赖，本版从运行流程中移除了这条路径。

## 新的运行流程

1. 左键按下时记录鼠标下的原始窗口，而不是松开后再猜当前前台窗口。
2. 选词结束后，在显示咕嘎工具条前，将选词附近的局部画面与目标词近景缓存到内存。裁剪限制在当前显示器和来源窗口客户区域，避免把相邻软件纳入上下文。
3. 出现「解释／翻译」工具条。此时不发模型请求；不点击会在 8 秒后清空缓存并收起。再次点击其他软件会收起旧工具条。
4. 点解释／翻译时，将已缓存的选区近景和周围画面发送给当前配置的多模态模型。原窗口即使失去焦点，读取也不再依赖它。整个流程不恢复窗口焦点、不模拟 Ctrl+C、不修改剪贴板。
5. 临时问答窗展示选区预览，要求模型先引用高亮原文，再解释或翻译。关闭时清空图片、上下文和对话；不会写入正式聊天历史或技能记忆。

Ctrl+Alt+E 使用鼠标附近高亮选区的同一路径。图片中的文字也依赖实际高亮或选取位置；若画面看不出选中了哪段，模型应明确说明，不能把整段文字冒充选区。

## 已验证内容

- 88 项离线回归通过，包括来源窗口按鼠标按下位置记录、读取前缓存、焦点改变后仍能使用缓存、取消过期缓存、关闭清理、图片进入临时模型请求及原语音／任务／音乐相关回归。
- 原生屏幕链路测试使用自动生成的文本窗口，在屏幕上高亮 `interface`，实际经过局部截图 → 工具条按钮 → 当前 Go DeepSeek API → 临时解释窗。两项结果均引用 `interface`，解释为程序间交换信息的接口，翻译为「接口」。测试中将恢复焦点与模拟按键函数设为调用即失败，两者均未被调用；剪贴板保持不变。
- 首次只传上下文画面时，解释结果误带了相邻的 `An`。因此增加目标词近景并严格要求只引用高亮文字；重新进行了两次真实模型调用，最终解释和翻译均通过更严格的原文检查。本阶段合计 4 次小样本 API 调用。
- 测试窗口及测试进程均已结束，没有后台持续测试。证据在 runtime/selection-visual-20261029/result.json、fixture-selection.png、explain-preview.png、translate-preview.png。

## 尚未确认的范围

电脑操作工具能列出豆包浏览器，却反复拒绝读取该窗口，返回「window id no longer belongs ... current owner is ...」。已停止重试，没有绕过工具限制控制用户浏览器。本版已经验证了完整的新屏幕链路与实际模型调用，但用户原浏览器和所有软件仍需实际复测。

这是画面识别路径，可能受文字大小、选区底色、遮挡和跨屏选区影响。新增预览用于让用户检查捕获范围；没有把视觉识别包装成精确复制。
