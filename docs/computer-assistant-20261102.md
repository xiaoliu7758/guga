# 咕嘎屏幕辅助诊断与电脑操作增强

源码版本：`2026-11-02.computer-assistant.1`。本文区分源码改动、离线回归、真实浏览器验收和当前常驻加载状态。

## 1. 为什么长对话中像是没有共享屏幕

发现了三处确切的实现问题，但没有足够历史记录把某一次用户体验唯一归因到其中一处。

1. **通话入口分裂。** 右键菜单里的“千问长语音通话”原来调用 `PetWindow._open_realtime_voice`，创建纯音频 `RealtimeVoice`；它不创建执行智能体，也不启动 `ScreenShareController`。“长语音 · 边聊边执行”才调用智能体通话及屏幕采集。现在旧入口转发到同一个智能体入口，菜单名称也明确包含屏幕辅助与任务执行。
2. **首次失败没有恢复。** 原 `_start_call_screen_share` 吞掉启动异常，并把通话所有权设为 false；恢复定时器只有首次启动成功后才启动。现在先登记通话的共享意图并启动守望；错误显示在状态及本地生命周期诊断中，最多累计三次失败，30秒恢复间隔。手动停止共享后不恢复，普通任务仍不自启共享。
3. **提示词与画面资料时效。** 执行模型仍被告知“并非持续共享屏幕”，语音模型却被告知宿主默认取景。现在统一说明宿主实际状态，屏幕问题必须交给执行层读取工具。静止画面持续采样确认未变时可沿用摘要，避免12秒后无条件失效；窗口或画面改变后旧摘要失效。分析期间发生的变化也不会被一次迟到的结果覆盖为“新鲜”。失败静态帧最多补试两次，受原限流与退避约束。

**本轮实时观察：** 准备加载前发现当前实例正在通话和执行任务，因而取消重启。只读状态确认旧实例 `voice-assistant.6` 的 `voice_active=true`、共享 `active=true`、原因 `call`；采集319帧、分析成功11次、分析错误0次，最新帧距查询0.17秒。此时确实有本机采集，不能把模型说“看不到”当作共享未启动的证据。

现有千问调用链未发送图像消息。屏幕帧由宿主采集，抽样后生成视觉摘要，交给执行模型辅助任务；这不等于千问音频连接直接接收视频。

## 2. 共享屏幕能带来多大提升

| 日常任务 | 预期作用 | 主要限制与更可靠的执行依据 |
|---|---|---|
| “点这里”“这个页面”“刚才那个错误” | 帮助识别前台、理解指代和发现弹窗 | 先核对窗口身份、摘要时效；精确操作读取控件或最新截图 |
| 中文填表、金额、日期、长编号 | 有助于理解表单整体布局 | 视觉摘要会漏字、错字；结构化字段定位和回读更适合精确输入 |
| 多步骤网页操作 | 有助于观察页面状态及恢复上下文 | 截图不提供稳定控件身份；DOM工具、分页状态和提交回执更关键 |
| 跨应用任务 | 有助于知道用户当前停在哪个软件 | 仍依赖 Windows UIA、窗口聚焦和输入后的核验 |
| 文件整理、命令计算 | 通常收益有限 | 文件、进程和退出码等直接工具更可靠、更省请求 |
| 视频、快速动画、游戏实时反应 | 只能提供粗粒度环境信息 | 本地2—5fps采集、每分钟默认最多6次视觉分析，无法提供实时逐帧控制 |

客观结论：共享屏幕补足环境感知和任务交接；精确电脑操作还需要结构化控件、操作状态与结果核验。本轮没有同任务开关共享的对照实验，不能提供可靠的总体成功率提升百分比。模型延迟、视觉误读、后台窗口不可见和画面中的提示注入仍需在工具边界处理。画面和网页内容始终是资料，不能成为新的任务指令。

本机采样与变化检测不调用模型；关键帧视觉分析会调用现有配置的服务并消耗相应额度。2fps本地采样不代表每秒两次模型请求。当前帧不写截图或录像；长通话结束会清除帧和摘要。专用浏览器的登录资料单独存于本地profile，不能把“屏幕帧仅内存”理解成整个浏览器不落盘。

以上为机制参考；没有复制这些项目的代理实现，也没有把上游演示或基准当成本机能力。本机已有Playwright与Chromium，本轮没有安装额外组件、云浏览器服务或新模型。

## 4. 现在具体能做什么

`browser` 新增 `session_start/session_status/session_stop/tabs/new_tab/snapshot/navigate/fill_form/click/press/scroll/wait/upload/download`。原 `open/close_tab` 保持现有默认浏览器路径。

- 专用浏览器默认可见，独立profile可由用户手动登录，之后保留登录态；不会自动接管个人浏览器中已经打开的标签。用户明确要求操作现有页面时，仍先用原有窗口与UIA路径。
- 每次观察提供 `page_id`、`snapshot_id` 和当前控件 `ref`，支持iframe。输入必须使用同一页、60秒内、尚未消耗的观察；禁止猜ref。一次批量最多30个字段，支持文字、下拉选项和勾选，逐字段回读。字段填写不自动提交。
- 点击、按键、上传和下载需要 `operation_id`；同ID同操作返回原回执，不重新发送；同ID换操作被拒绝。失败回执保留是否已发送和已验证字段。点击后仍需读取目标页面核验业务成功，不能只凭点击工具成功就宣告提交成功。
- 上传仅选择明确的本地文件；下载核验实际本地文件。任务指令仍决定是否授权上传、提交、发送或其他外部副作用。
- 浏览器位于独立工作进程，单次宿主调用最多35秒；页面导航和控件操作另有更短上限。取消或超时会清理该工作进程及其浏览器子进程，结果未知时不自动重放提交。300秒无操作自动结束；宿主退出也清理专用会话。
- 本地执行器和DSH共用同一个工具定义、执行器及回执规则；多步表单本身不因此被升级为工程任务。

这已覆盖常见表单、多步页面、iframe、多标签和文件往返的基础能力。复杂验证码、站点反自动化、需要本人登录、多窗口原生文件对话框、自绘canvas控件等没有在本轮全面验证，不能承诺任意复杂网站全自动完成。
